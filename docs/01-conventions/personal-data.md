# Персональные данные

Роботы часто обрабатывают персональные данные: ФИО, паспортные данные, телефоны, адреса, СНИЛС, данные о здоровье. Обработка персональных данных в России регулируется Федеральным законом № 152-ФЗ «О персональных данных», а также внутренними политиками компании. Робот — такой же участник обработки, как и сотрудник, и на него распространяются те же требования.

Раздел не заменяет консультацию службы информационной безопасности. Если робот обрабатывает персональные данные, согласуйте его с ИБ на этапе проектирования (см. [Проектирование](../03-robot-lifecycle/design.md)).

## PD-01. Обрабатывайте только необходимые персональные данные

**Уровень:** MUST — обязательно

Робот получает, хранит и передает только те персональные данные, которые нужны для выполнения процесса.

- Не кладите в элемент очереди всю строку из исходной системы, если для обработки нужны два поля
- Не выгружайте полную таблицу клиентов ради поиска одного клиента — фильтруйте в запросе (см. [DB-02](database.md#db-02-выполняйте-фильтрацию-в-sql-запросах-а-не-в-коде))
- Не сохраняйте промежуточные файлы с персональными данными дольше, чем идет обработка транзакции

## PD-02. Не допускайте персональные данные в логи, статусы и имена файлов

**Уровень:** MUST — обязательно

Логи, статусы элементов очереди и имена файлов видит широкий круг людей: поддержка, администраторы, разработчики. Персональные данные туда не попадают.

| Место | Неправильно | Правильно |
|-------|-------------|-----------|
| Лог | `Обработан клиент Иванов Иван, паспорт 4510 123456` | `[Q-10452] Обработан клиент ID 88213` |
| Статус элемента очереди | `Ошибка: не найден Петров П.П.` | `Ошибка: клиент не найден в CRM (ID 88213)` |
| Имя файла | `Заявление_Иванов_И_И.pdf` | `Заявление_88213.pdf` |
| Текст исключения | `Неверный СНИЛС 123-456-789 00` | `Неверный формат СНИЛС` |

Способы маскирования описаны в [LOG-06](logging.md#log-06-не-логируйте-конфиденциальные-данные).

## PD-03. Ограничивайте доступ к скриншотам и артефактам с персональными данными

**Уровень:** MUST — обязательно

Скриншоты ошибок, выгрузки, временные и отладочные файлы могут содержать персональные данные, даже если робот не записывает их явно.

- Храните такие артефакты в папках с доступом только для робота и поддержки
- Задайте срок хранения и автоматическое удаление (например, 30 дней для скриншотов ошибок)
- Не пересылайте скриншоты с персональными данными в чаты и письма; передавайте ссылку на защищенное хранилище
- Если скриншот не нужен для разбора, не делайте его

## PD-04. Используйте обезличенные данные для разработки и тестирования

**Уровень:** MUST — обязательно

На контурах DEV и UAT используйте синтетические или обезличенные данные. Копирование продуктивных персональных данных в тестовую среду допустимо только по согласованию с ИБ.

- Тестовые файлы и выгрузки в репозитории не содержат реальных персональных данных (см. [GIT-05](git.md#git-05-не-коммитьте-конфиденциальные-данные))
- Для отладки продуктивной ошибки воспроизводите ее на обезличенной копии данных, а не на рабочем контуре с отладчиком

## PD-05. Не передавайте персональные данные во внешние сервисы без согласования

**Уровень:** MUST — обязательно

Передача данных во внешний сервис — это передача третьему лицу. Это относится к облачному OCR, сервисам перевода, внешним API и особенно к LLM-сервисам (см. [ИИ и распознавание документов](../02-guidelines/ai-and-idp.md)).

- Передача персональных данных во внешний сервис согласуется с ИБ и фиксируется в SDD робота
- Если сервис можно развернуть внутри контура компании, предпочитайте внутренний вариант
- Если согласования нет, перед отправкой удаляйте или заменяйте персональные данные
