## Робот и проект

| Термин | Определение |
|--------|-------------|
| **Робот** | Общее название автоматизации процесса. В PIX Master отдельной сущности «робот» нет: робот складывается из проекта, задачи и агента. Фраза «робот упал» обычно значит, что задача завершилась с ошибкой. Без мастера робот сводится к проекту, который запускают из PIX Studio, PIX Runner или `robot.exe` |
| **Unattended-робот** (фоновый робот) | Робот, который работает без участия человека. Запускается мастером по расписанию или по событию и работает на машине в своей сессии, на Windows это RDP-сессия учетной записи агента. Подходит для процесса целиком: обработка заявок, сверка, загрузка реестров. В PIX Master такой робот работает через агента |
| **Attended-робот** (робот-помощник, ассистент) | Робот, который работает на компьютере сотрудника в его сессии и запускается им по требованию. Берет на себя часть работы сотрудника: заполнить форму, собрать данные по клиенту. Может запросить у человека данные или подтверждение. Обычно запускается через PIX Runner или вызовом `robot.exe` с командами из консоли |
| **PIX Runner** | Приложение сотрудника для работы с роботами в формате чата: каждый робот выглядит отдельным контактом. В чате сотрудник запускает и останавливает робота, получает от него сообщения и отвечает на запросы. Через подключение к PIX Master загружает проекты и запускает задачи мастера |
| **Проект** | Код робота: файл проекта `.pixproj`, скрипты `.pix` и нужные им файлы. Описывает, что делать. Скрипт `.pix` можно открыть и запустить и без `.pixproj`, но тогда это отдельный скрипт, а не робот. В PIX Master загружается архивом, у каждой загрузки своя версия |
| **Скрипт PIX** (`.pix`) | Файл проекта с последовательностью активностей. Проект состоит из стартового скрипта, который указывают при загрузке в PIX Master, и скриптов, которые он вызывает. Скрипт принимает параметры и возвращает результат, как функция. См. [TEMPLATE-01](1-project/template.md#template-01-раскладывайте-скрипты-по-папкам-по-роли), [«Сценарий транзакции»](1-project/template.md#сценарий-транзакции-паттерн-transaction-script) |
| **Чистая функция** | Скрипт, который на одних входных данных всегда дает один результат и ничего не меняет вокруг: не обращается к внешним системам и не читает переменные `main.pix`. Например, разбор номера заказа из строки. Такие скрипты лежат в `Helpers` и тестируются без запуска робота. См. [TEMPLATE-01](1-project/template.md#template-01-раскладывайте-скрипты-по-папкам-по-роли) |
| **Активность** | Готовое действие в PIX Studio: открыть приложение, нажать кнопку, прочитать Excel, положить элемент в очередь. Из активностей собираются скрипты PIX. Активности подключаются к проекту NuGet-пакетами. Если готовой активности нет, действие пишут на C# |
| **NuGet-пакет** | Архив с библиотекой .NET, ее версией и списком зависимостей; стандартный способ распространять код в .NET. В PIX Studio через NuGet-пакеты подключаются активности, а робот может подключать и другие пакеты .NET. Studio берет пакеты из хранилища зависимостей PIX Master или из внешних источников (nuget.pix.ru, nuget.org). Пакеты проекта и их версии записаны в `packages.config`, источники пакетов в `nuget.config`. Робот подключает пакет конкретной версии ([PROJECT-03](1-project/project.md#project-03-согласуйте-подключение-собственной-библиотеки)). Как подключить пакет: [«Подключение NuGet-пакетов в PIX Studio»](1-project/project.md#подключение-nuget-пакетов-в-pix-studio) |
| **Библиотека** | Собственный общий код команды или компании, который подключают несколько роботов: набор активностей или методов C#, обычно в виде NuGet-пакета. Публичные пакеты с nuget.org (ClosedXML, MailKit) к библиотекам в этом смысле не относятся. В библиотеке нет правил отдельных процессов. Подключение согласуют с тимлидом или ревьюером, робот подключает конкретную версию. Ошибка в новой версии ломает всех роботов, которые на нее обновились. См. [PROJECT-03](1-project/project.md#project-03-согласуйте-подключение-собственной-библиотеки) |
| **Ресурс робота** | Файл, который робот использует в работе и который публикуется вместе с проектом: шаблон отчета Excel, шаблон письма HTML, образец документа. Не путайте с ассетом: ассет хранится в PIX Master, а ресурс в проекте робота. См. [PROJECT-02](1-project/project.md#project-02-храните-ресурсы-робота-в-самом-проекте) |
| **Входной параметр робота** | Параметр стартового скрипта проекта, обычно `main.pix`; в PIX Studio он так и называется. Значение задают в задаче PIX Master или передают при запуске: дата отчета, номер заявки, режим работы. Меняется от запуска к запуску. Настройки, которые от запуска не зависят, хранятся в ассетах. См. [CONFIG-03](1-project/config.md#config-03-используйте-входные-параметры-робота-только-для-значений-запуска) |

## Шаблон и состояния

| Термин | Определение |
|--------|-------------|
| **Шаблон проекта** | Готовая структура проекта робота, с которой начинают разработку: папки, состояния, обработка ошибок, логирование, чтение конфигурации. Шаблон выбирают по типу процесса ([PROJECT-01](1-project/project.md#project-01-выбирайте-шаблон-по-типу-процесса)). Готовые шаблоны лежат в репозитории [pix-templates](https://github.com/TheMrDJek/pix-templates) |
| **State Machine** (конечный автомат) | Способ построить шаблон проекта как набор состояний и переходов между ними. В каждый момент робот находится в одном состоянии. После каждого исхода (успех, бизнес-исключение, техническое исключение, данных больше нет) переход заранее определен, поэтому ошибки обрабатываются в одном месте, а робот может восстановиться и продолжить. Транзакционному процессу нужны четыре состояния Init → Get Transaction → Process Transaction → End Process, линейному хватает трех, без Get Transaction. См. [PROJECT-01](1-project/project.md#project-01-выбирайте-шаблон-по-типу-процесса), [TEMPLATE-02](1-project/template.md#template-02-выполняйте-в-каждом-состоянии-только-его-работу), [«Плюсы и минусы State Machine»](1-project/project.md#плюсы-и-минусы-state-machine) |
| **REFramework** (Robotic Enterprise Framework) | Шаблон транзакционного робота на State Machine от UiPath, ставший стандартом в RPA. Описывает четыре состояния, разделение бизнес- и технических исключений, повторы и восстановление приложений. Шаблоны PIX построены по той же схеме |
| **Dispatcher / Performer** (поставщик / обработчик, producer / consumer) | Схема, а не шаблон проекта: процесс делится на две стороны, связанные очередью. Dispatcher кладет транзакции в очередь, Performer забирает их по одной и обрабатывает. Поставщиком может быть не только робот, а очередью не только очередь PIX Master. См. [справку](1-project/project.md#dispatcher--performer-когда-делить-процесс-на-несколько-роботов) |
| **Transaction Script** (сценарий транзакции) | Паттерн из каталога Мартина Фаулера ([Patterns of Enterprise Application Architecture](https://martinfowler.com/eaaCatalog/transactionScript.html)): каждая операция системы реализуется своей процедурой от начала до конца. Это не паттерн DDD, а простая альтернатива модели предметной области. У робота каждый тип транзакции получает свой сценарий: короткий скрипт, который по порядку вызывает шаги, а не один скрипт на сотни активностей. См. [«Сценарий транзакции»](1-project/template.md#сценарий-транзакции-паттерн-transaction-script) |
| **Стратегия** (Strategy) | Паттерн, при котором робот делится на общий движок и взаимозаменяемые стратегии. У стратегий одинаковый вход и один формат результата, друг от друга они не зависят. Какие стратегии запускать, задает входной параметр задачи в PIX Master. Например, движок парсинга открывает браузер и загружает результат в BI, а стратегия извлекает данные с одного сайта. См. [«Варианты процесса: стратегия»](1-project/template.md#варианты-процесса-стратегия) |

## Транзакции и ошибки

| Термин | Определение |
|--------|-------------|
| **Транзакция** | Одна единица работы робота: данные и шаги для их обработки. Транзакции не зависят друг от друга: если одна упала, робот берет следующую. Например, одно письмо, один счет, одна строка реестра |
| **Бизнес-исключение** | Ошибка в данных транзакции: робот работает исправно, но обработать транзакцию по правилам процесса не может. Например, контрагента с таким ИНН нет в справочнике. Повтор не поможет. Робот вызывает `PIX.Core.Exceptions.BusinessRuleException` и берет следующую транзакцию. См. [ERROR-06](2-develop/error.md#error-06-разделяйте-бизнес-исключения-и-технические-исключения) |
| **Техническое исключение (системное)** | Любое исключение, кроме бизнес-исключения. Обычно это ошибка окружения: система не отвечает, файл заблокирован, окно не появилось или зависло. Повтор может помочь: для UI разработчик предусматривает повтор действия, без UI повторяется транзакция целиком ([QUEUE-04](3-integrations/queue.md#queue-04-правильно-обрабатывайте-повторные-попытки-retry)). Повтор не должен создавать дублей ([RECOVERY-01](2-develop/recovery.md#recovery-01-делайте-обработку-транзакции-идемпотентной)). См. [ERROR-06](2-develop/error.md#error-06-разделяйте-бизнес-исключения-и-технические-исключения) |
| **Fail fast** («падай рано») | Принцип: ошибку окружения или настройки ищут как можно раньше, пока робот еще ничего не изменил. Поэтому Init проверяет настройки и доступ ко всем системам до первой транзакции, и робот с ошибкой падает в Init, а не посреди транзакции. См. [TEMPLATE-02](1-project/template.md#init), [TEMPLATE-03](1-project/template.md#template-03-проверяйте-в-init-настройки-и-доступ-ко-всем-системам-робота) |
| **Повтор** (retry) | Новая попытка после технического исключения. Бизнес-исключение не повторяется. Повторы идут на трех уровнях, которые не зависят друг от друга: в запуске робот повторяет Init или транзакцию, очередь PIX Master возвращает элемент на обработку позже, задача PIX Master запускается заново. Поэтому попытки уровней перемножаются. См. [TEMPLATE-02](1-project/template.md#template-02-выполняйте-в-каждом-состоянии-только-его-работу), [QUEUE-04](3-integrations/queue.md#queue-04-правильно-обрабатывайте-повторные-попытки-retry) |
| **Идемпотентность** | Свойство операции: если выполнить ее повторно, результат будет тем же, что после первого раза, и ничего не задвоится. Для робота это значит, что повтор транзакции после сбоя не создает второй документ и не отправляет второе письмо. Есть два способа. Робот перед необратимым шагом проверяет в целевой системе, не сделан ли он: например, ищет в 1С заказ с этим номером. Или робот ставит метку после каждого этапа: сохранил карточку заявки, ставит в элементе очереди метку «карточка сохранена»; при повторе видит метку и сразу переходит к проведению. См. [RECOVERY-01](2-develop/recovery.md#recovery-01-делайте-обработку-транзакции-идемпотентной), [QUEUE-10](3-integrations/queue.md#queue-10-отмечайте-в-элементе-очереди-выполненные-необратимые-шаги) |

## PIX Master

| Термин | Определение |
|--------|-------------|
| **PIX Master** (мастер, оркестратор) | Серверный компонент PIX RPA для управления роботами, расписаниями, очередями и ассетами |
| **Ассет** | Параметр робота, который хранится в PIX Master, в разделе **«Данные» (Data)**. Робот получает значение по ключу при запуске. Значение бывает общим или своим для агента. Подробно: [Что такое ассет](1-project/config.md#что-такое-ассет) |
| **Контур** (среда, стенд, environment) | Отдельный набор всего, с чем работает робот: машины, целевые системы и их данные, ассеты в PIX Master. Контуры изолированы: робот на DEV не трогает данные PROD. На DEV разрабатывают, на UAT тестируют и принимают, на PROD робот работает с реальными данными. Код робота на всех контурах один, различаются значения ассетов ([PUBLISH-02](4-master/publish.md#publish-02-продвигайте-одну-и-ту-же-сборку-по-контурам-dev--uat--prod)) |
| **Очередь данных** | Встроенный в PIX Master брокер сообщений: хранит транзакции и выдает их роботам по одной. Кроме очереди мастера, роботы могут работать с внешними брокерами, например RabbitMQ или Kafka. Как устроена очередь мастера: [Об очередях PIX Master](3-integrations/queue.md#об-очередях-pix-master), [документация PIX Master](https://docs.pixrobotics.com/articles/#!rpa/master-queues) |
| **Элемент очереди** | Транзакция, сохраненная в очереди данных PIX Master, со статусом обработки. Поля и статусы описаны в [документации PIX Master](https://docs.pixrobotics.com/articles/#!rpa/master-queues). См. [QUEUE-02](3-integrations/queue.md#queue-02-обрабатывайте-элемент-очереди-как-транзакцию) |
| **Ссылка элемента очереди** (reference) | Дополнительный идентификатор элемента: ключ транзакции из источника, например номер счета, ID письма или номер заявки. Если в очереди включена проверка уникальности ссылок, мастер не добавит второй элемент с той же ссылкой. См. [QUEUE-09](3-integrations/queue.md#queue-09-задавайте-элементу-очереди-уникальную-ссылку) |
| **SLA** (Service Level Agreement) | Согласованный срок, за который работа должна быть выполнена. У элемента очереди PIX Master SLA задается в секундах с момента создания элемента. Если элемент не обработан за это время, мастер отмечает превышение SLA, но обработку не прекращает |
| **Задача** | Настройка запуска в PIX Master: какой проект и какую его версию запускать, с какими параметрами и на каких агентах. Каждый запуск задачи запускает робота один раз |
| **Очередь задач** | Очередь запусков задач в PIX Master. Не путать с очередью данных: здесь ждут запуски роботов, а не транзакции. Если агент занят, запуск ждет в очереди задач, а не завершается ошибкой. Строгая очередь запускает задачи строго по порядку, гибридная пропускает вперед задачу, которая может выполниться сейчас. Задача без очереди попадает в очередь Default |
| **Cron-выражение** | Строка, которой задают расписание запуска. PIX Master использует формат Quartz: поля идут в порядке секунды, минуты, часы, день месяца, месяц, день недели. Например, `0 0 9 ? * MON-FRI` означает 9:00 по будням |
| **Процесс мастера** | Схема из блоков в PIX Master: запуск задач, условия, работа с очередями, почта, ожидание. Связывает несколько задач в цепочку или подстраховывает запуск по событию: проверяет очередь и запускает робота, если в ней есть элементы. Не путать с бизнес-процессом, который автоматизирует робот. См. [QUEUE-12](3-integrations/queue.md#queue-12-запускайте-обработку-очереди-по-событию-и-подстраховывайте-процессом) |
| **Машина** (хост, сервер робота) | Сервер, на котором работают роботы, и его запись в PIX Master. На машине работает несколько агентов, каждый под своей учетной записью. Сколько роботов работает одновременно, зависит от числа одновременных RDP-подключений, разрешенных лицензиями |
| **Агент** | Программа PIX Agent, которая получает задачи от мастера и запускает проект. В PIX Master агент привязан к машине и к учетной записи Windows, под которой он подключается к машине по RDP. Агент выполняет одну задачу за раз |
| **PIX Agent Host Service** | Служба Windows на машине. По команде мастера открывает сессию, запускает агента и после задачи выключает его. Без службы агент остается обычной программой: после перезагрузки сервера ее никто не запустит |

## Интеграции и данные

| Термин | Определение |
|--------|-------------|
| **API** | Программный интерфейс системы: набор запросов, через которые другая программа читает и меняет данные без пользовательского интерфейса. Например, запрос «создать счет» с данными в JSON вместо заполнения формы. Через API робот работает надежнее и быстрее, чем через UI. См. [INTEGRATION-01](3-integrations/integration.md#integration-01-выбирайте-канал-интеграции-по-надежности-api--бд--файлы--ui) |
| **Interop (COM)** | Способ управлять приложением Windows через его COM-объекты, например `Excel.Application`: код или активность запускает само приложение. В PIX Studio активности Excel построены на двух библиотеках. Активности NPOI работают с файлом напрямую и не требуют установленного Microsoft Office, активности Interop запускают Excel. Excel и Outlook через Interop соглашение запрещает: [EXCEL-01](3-integrations/excel.md#excel-01-не-используйте-excel-interop-и-com), [MAIL-01](3-integrations/mail.md#mail-01-работайте-с-почтой-по-протоколам-а-не-через-outlook) |
| **Селектор** (XPath) | Описание, по которому робот находит элемент интерфейса: кнопку, поле, строку таблицы. Задается свойствами элемента (имя, тип, id) или путем XPath. Хороший селектор опирается на устойчивые свойства и не ломается от мелких изменений интерфейса. См. [UI-01](2-develop/ui.md#ui-01-не-используйте-абсолютные-xpath-пути), [UI-02](2-develop/ui.md#ui-02-ищите-элементы-desktop-ui-по-уникальным-свойствам) |
| **Selenium** (веб-драйвер) | Библиотека, которая управляет браузером через веб-драйвер, без расширения PIX. Робот автоматизирует браузер двумя способами: активностями PIX через расширение браузера или через Selenium. |
| **ПДн** (персональные данные) | Любые сведения, по которым можно определить человека: ФИО, телефон, паспорт, адрес, СНИЛС. Их обработку регулирует 152-ФЗ, поэтому робот берет только нужные для задачи данные, не пишет их в логи и не копирует на тестовые контуры. См. [PRIVACY-01](2-develop/privacy.md#privacy-01-обрабатывайте-только-необходимые-персональные-данные) |
| **OCR** (Optical Character Recognition) | Распознавание текста на изображении: скане документа, фотографии, скриншоте. OCR возвращает текст без структуры, поля документа из него извлекает IDP или VLM |
| **IDP** | Intelligent Document Processing: извлечение данных из документов с помощью OCR и моделей машинного обучения |
| **LLM** | Большая языковая модель |
| **VLM** (Vision Language Model) | Визуально-языковая модель: языковая модель, которая принимает на вход и изображения. Робот передает ей скан документа или скриншот и получает текст или поля документа |
| **Ручная проверка** (human-in-the-loop) | Проверка результата робота или модели человеком, прежде чем результат пойдет дальше. См. [AI-03](2-develop/ai.md#ai-03-направляйте-неуверенные-результаты-на-проверку-человеку) |

## Документы

| Термин | Определение |
|--------|-------------|
| **ТЗ, ЧТЗ** (PDD) | Техническое задание, частное техническое задание: описание процесса с точки зрения бизнеса. Что делает робот, по каким правилам, какие бывают бизнес-исключения |
| **ТП** (SDD) | Технический проект: описание технического решения робота. Архитектура, интеграции, ассеты, очереди и причины выбранных решений |
| **Runbook** (инструкция по сопровождению, руководство администратора, регламент сопровождения) | Инструкция для поддержки: как проверить работу робота и что делать при типовых проблемах |
