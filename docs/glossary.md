# Глоссарий

| Термин | Определение |
|--------|-------------|
| **Ассет** | Параметр робота, который хранится в PIX Master, в разделе **«Данные» (Data)**. Робот получает значение по ключу при запуске. Значение бывает общим или своим для агента. Подробно: [Что такое ассет](1-project/config.md#что-такое-ассет) |
| **Бизнес-исключение** | Ошибка в данных транзакции: робот работает исправно, но обработать транзакцию по правилам процесса не может. Например, контрагента с таким ИНН нет в справочнике. Повтор не поможет. Робот вызывает `PIX.Core.Exceptions.BusinessRuleException` и берет следующую транзакцию. См. [ERROR-06](2-develop/error.md#error-06-разделяйте-бизнес-исключения-и-технические-исключения) |
| **Техническое исключение (системное)** | Любое исключение, кроме бизнес-исключения. Обычно это ошибка окружения: система не отвечает, файл заблокирован, окно не появилось или зависло. Повтор может помочь: для UI разработчик предусматривает повтор действия, без UI повторяется транзакция целиком ([QUEUE-04](3-integrations/queue.md#queue-04-правильно-обрабатывайте-повторные-попытки-retry)). Повтор не должен создавать дублей ([RECOVERY-01](2-develop/recovery.md#recovery-01-делайте-обработку-транзакции-идемпотентной)). См. [ERROR-06](2-develop/error.md#error-06-разделяйте-бизнес-исключения-и-технические-исключения) |
| **Транзакция** | Одна единица работы робота: данные и шаги для их обработки. Транзакции не зависят друг от друга: если одна упала, робот берет следующую. Например, одно письмо, один счет, одна строка реестра |
| **Элемент очереди** | Транзакция, сохраненная в очереди данных PIX Master, со статусом обработки. Поля и статусы описаны в [документации PIX Master](https://docs.pixrobotics.com/). См. [QUEUE-02](3-integrations/queue.md#queue-02-обрабатывайте-элемент-очереди-как-транзакцию) |
| **Контур** | Изолированная среда: DEV (разработка), UAT (тестирование и приемка), PROD (продуктивная работа) |
| **PIX Master (мастер, оркестратор)** | Серверный компонент PIX RPA для управления роботами, расписаниями, очередями и ассетами |
| **Хост** | Сервер или рабочая станция, на которой выполняются роботы |
| **Агент робота** | Экземпляр робота в PIX Master, который выполняет задачи на хосте |
| **Unattended-робот** | Робот, работающий без участия человека по расписанию или триггеру |
| **Attended-робот** | Робот-помощник, запускаемый пользователем на его рабочем месте |
| **State Machine** | Шаблон робота, в котором работа разбита на состояния (Init, Get Transaction, Process Transaction, End Process) и переходы между ними |
| **Dispatcher / Performer** | Схема из двух роботов: Dispatcher загружает транзакции в очередь, Performer их обрабатывает. См. [PROJECT-06](1-project/project.md#project-06-разделяйте-загрузку-и-обработку-транзакций-dispatcher--performer) |
| **Transaction Script** | Паттерн, в котором каждый бизнес-сценарий реализуется одной процедурой. См. [PROJECT-07](1-project/project.md#project-07-организуйте-бизнес-логику-транзакции-по-паттерну-transaction-script) |
| **Идемпотентность** | Свойство операции давать тот же результат при повторном выполнении. См. [RECOVERY-01](2-develop/recovery.md#recovery-01-делайте-обработку-транзакции-идемпотентной) |
| **PDD** | Process Definition Document — описание процесса с точки зрения бизнеса |
| **SDD** | Solution Design Document — описание технического решения робота |
| **Runbook** | Инструкция для поддержки: как проверить работу робота и что делать при типовых проблемах |
| **UAT** | User Acceptance Testing — приемочное тестирование владельцем процесса |
| **Hypercare** | Период усиленного наблюдения за роботом после запуска |
| **IDP** | Intelligent Document Processing — извлечение данных из документов с помощью OCR и моделей машинного обучения |
| **LLM** | Большая языковая модель |
| **Human-in-the-loop** | Проверка результата робота или модели человеком перед использованием |
| **🔴 Обязательно / 🟡 Рекомендуется / 🟢 По ситуации** | Уровни обязательности правил. См. [README](../README.md#уровни-обязательности) |
