# Интеграции с внешними системами

Робот получает и передает данные через разные каналы: API, базы данных, файлы, почту и пользовательский интерфейс. От выбора канала зависит, как часто робот будет ломаться и сколько стоит его поддержка.

## INTEGRATION-01. Выбирайте канал интеграции по надежности: API → БД → файлы → UI

🟡 **Рекомендуется**

UI-автоматизация ломается чаще других каналов: от обновления интерфейса, разрешения экрана, всплывающего окна. Используйте ее, только если более надежного канала нет.

| Приоритет | Канал | Надежность | Когда использовать |
|-----------|-------|------------|--------------------|
| 1 | API (REST, SOAP) | Высокая: контракт документирован и версионируется | Есть API с нужными методами и к нему можно получить доступ |
| 2 | База данных | Высокая для чтения, ограниченная для записи | Чтение данных; запись только с разрешения владельца системы и если она не обходит бизнес-логику приложения |
| 3 | Файлы и почта (выгрузки, обмен) | Средняя: зависит от формата и расписания выгрузки | Система умеет выгружать и загружать данные в файлы |
| 4 | UI (web, desktop) | Низкая | Других каналов нет или их получение займет несоразмерно много времени |

**Правила:**
- Выбор канала для каждой системы фиксируется в ТП с обоснованием
- Если выбран UI, хотя API существует, в ТП указывается причина (нет доступа, нет нужного метода, сроки)
- Не записывайте данные напрямую в таблицы чужой системы, если это обходит ее проверки и бизнес-логику
- Каналы можно комбинировать: чтение через БД, создание документа через UI

## INTEGRATION-02. Задавайте таймауты для всех внешних вызовов

🔴 **Обязательно**

Любой вызов внешней системы (HTTP-запрос, запрос к БД, ожидание письма, ожидание элемента UI) должен иметь явный таймаут. Вызов без таймаута при зависании системы-партнера приводит к зависанию робота на неопределенное время.

```csharp
// HTTP-клиент: явный таймаут
var httpClient = new HttpClient { Timeout = TimeSpan.FromSeconds(apiTimeoutSeconds) };

// Запрос к БД: явный таймаут команды
command.CommandTimeout = dbTimeoutSeconds;
```

- Значения таймаутов храните в ассетах (см. [CONFIG-05](../1-project/config.md#config-05-не-используйте-жесткое-кодирование))
- Истекший таймаут считается техническим исключением (см. [ERROR-06](../2-develop/error.md#error-06-разделяйте-бизнес-исключения-и-технические-исключения))
- Для циклов ожидания действует [LOOP-01](../2-develop/loop.md#loop-01-ограничивайте-каждый-цикл-таймаутом-или-числом-итераций)

## INTEGRATION-03. Используйте отдельные учетные записи робота для каждой системы

🔴 **Обязательно**

Робот подключается к внешним системам под собственными техническими учетными записями, а не под учетной записью разработчика или сотрудника.

- Действия робота в журналах целевой системы отличимы от действий людей
- Права учетной записи ограничены тем, что нужно процессу
- Смена пароля сотрудника или его увольнение не останавливает робота
- Учетные данные хранятся в ассетах типа «Учетные данные» (см. [CONFIG-02](../1-project/config.md#config-02-используйте-зашифрованные-ассеты-для-хранения-конфиденциальных-данных))

## INTEGRATION-04. Выполняйте HTTP-запросы через HttpClient

🟡 **Рекомендуется**

Для запросов к REST API используйте `HttpClient` (или HTTP-активности PIX RPA, если их возможностей достаточно). Не используйте устаревшие `WebClient` и `HttpWebRequest`: Microsoft не рекомендует их для новой разработки.

**Правила:**
- **Переиспользуйте один экземпляр `HttpClient`** на весь запуск робота: создайте его в Init, освободите в End Process. Создание нового `HttpClient` на каждый запрос исчерпывает сокеты при большом числе транзакций
- **Задавайте таймаут** явно (см. [INTEGRATION-02](#integration-02-задавайте-таймауты-для-всех-внешних-вызовов))
- **Проверяйте код ответа** и различайте ошибки: `4xx` обычно означает ошибку в данных или доступе (бизнес-исключение или ошибка конфигурации), `5xx` и таймауты означают техническое исключение с повтором (см. [ERROR-06](../2-develop/error.md#error-06-разделяйте-бизнес-исключения-и-технические-исключения))
- **Не собирайте URL конкатенацией** с пользовательскими данными: кодируйте параметры через `Uri.EscapeDataString`
- **Базовый адрес и учетные данные.** В ассетах; токены не логируются (см. [LOG-06](../2-develop/log.md#log-06-не-логируйте-конфиденциальные-данные))

```csharp
// Init: один клиент на весь запуск робота
var httpClient = new HttpClient
{
    BaseAddress = new Uri(apiBaseUrl),
    Timeout = TimeSpan.FromSeconds(apiTimeoutSeconds)
};
httpClient.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", apiToken);

// Process Transaction: запрос и проверка ответа
var response = httpClient.GetAsync($"customers/{Uri.EscapeDataString(customerId)}").Result;

if (response.StatusCode == HttpStatusCode.NotFound)
{
    var notFound = new InvalidOperationException($"Клиент {customerId} не найден в CRM");
    notFound.Data["ExceptionType"] = "Business";
    throw notFound;
}

response.EnsureSuccessStatusCode(); // 5xx и прочие ошибки — техническое исключение
var customerJson = response.Content.ReadAsStringAsync().Result;

// End Process
httpClient.Dispose();
```
