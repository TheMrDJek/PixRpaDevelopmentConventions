# Интеграции с внешними системами

Робот получает и передает данные через разные каналы: API, базы данных, файлы, почту и пользовательский интерфейс. От выбора канала зависит, как часто робот будет ломаться и сколько стоит его поддержка.

## INTEGRATION-01. Задавайте таймауты для всех внешних вызовов

🔴 **Обязательно**

Любой вызов внешней системы (HTTP-запрос, запрос к БД, ожидание письма, ожидание элемента UI) должен иметь явный таймаут. Вызов без таймаута при зависании системы-партнера приводит к зависанию робота на неопределенное время.

```csharp
// HTTP-клиент: явный таймаут
var httpClient = new HttpClient { Timeout = TimeSpan.FromSeconds(apiTimeoutSeconds) };

// Запрос к БД: явный таймаут команды
command.CommandTimeout = dbTimeoutSeconds;
```

- Значения таймаутов храните в ассетах (см. [CONFIG-01](../1-project/config.md#config-01-не-зашивайте-настройки-в-код))
- Истекший таймаут считается техническим исключением (см. [ERROR-03](../2-develop/error.md#error-03-разделяйте-бизнес-исключения-и-технические-исключения))
- Для циклов ожидания действует [LOOP-01](../2-develop/loop.md#loop-01-ограничивайте-каждый-цикл-таймаутом-или-числом-итераций)

## INTEGRATION-02. Используйте отдельные учетные записи робота для каждой системы

🔴 **Обязательно**

Робот подключается к внешним системам под собственными техническими учетными записями, а не под учетной записью разработчика или сотрудника.

- Действия робота в журналах целевой системы отличимы от действий людей
- Права учетной записи ограничены тем, что нужно процессу
- Смена пароля сотрудника или его увольнение не останавливает робота
- Учетные данные хранятся в ассетах типа «Учетные данные» (см. [CONFIG-05](../1-project/config.md#config-05-храните-секреты-в-защищенных-ассетах))

## INTEGRATION-03. Создавайте HttpClient один раз на запуск робота

🔴 **Обязательно**

Не создавайте `HttpClient` на каждый запрос. Создайте его в Init, сохраните в переменной `main.pix` и передавайте в скрипты входным параметром. В End Process освободите его методом `Dispose`. На ревью `new HttpClient` встречается только в Init.

**Где это случается.** Чаще всего во вставке кода внутри цикла. «Цикл для каждого» перебирает строки таблицы, а код в активности «Выполнить» на каждой строке создает клиент и отправляет запрос к LLM или API.

```csharp
// ❌ Плохо: код внутри «Цикла для каждого», новый клиент на каждую строку
using var httpClient = new HttpClient { Timeout = TimeSpan.FromSeconds(60) };
var response = httpClient.PostAsync(llmUrl, new StringContent(requestJson, Encoding.UTF8, "application/json")).Result;

// ✅ Хорошо: клиент создан в Init и пришел входным параметром
var response = in_LlmHttpClient.PostAsync(llmUrl, new StringContent(requestJson, Encoding.UTF8, "application/json")).Result;
```

**Чем опасен клиент на каждый запрос.** После `Dispose` Windows еще несколько минут держит сокет занятым. Цикл из сотен запросов занимает свободные порты, и очередной запрос падает с `SocketException`, хотя API работает. Каждый новый клиент к тому же заново открывает соединение и TLS, и цикл идет медленнее.

**Как оформлять:**
- Робот работает с несколькими API: заведите по клиенту на систему, у каждой свой адрес и заголовки: `crmHttpClient`, `llmHttpClient`
- Скрипт вызывают отдельно от шаблона, и клиента из Init нет: создайте клиент перед циклом в том же скрипте и освободите после цикла
- Робот работает часами без перезапуска: задайте клиенту `PooledConnectionLifetime`, чтобы он заметил смену адреса сервера в DNS

```csharp
// Init: клиент для долгого запуска пересоздает соединения раз в 15 минут
var llmHttpClient = new HttpClient(new SocketsHttpHandler { PooledConnectionLifetime = TimeSpan.FromMinutes(15) })
{
    BaseAddress = new Uri(config["LlmApiUrl"]),
    Timeout = TimeSpan.FromSeconds(60)
};
```

## INTEGRATION-04. Выбирайте канал интеграции по надежности: API → БД → файлы → UI

🟡 **Рекомендуется**

UI-автоматизация ломается чаще других каналов: от обновления интерфейса, разрешения экрана, всплывающего окна. Используйте ее, только если более надежного канала нет.

| Приоритет | Канал | Надежность | Когда использовать |
|-----------|-------|------------|--------------------|
| 1 | API (REST, SOAP) | Высокая: контракт документирован и версионируется | Есть API с нужными методами и к нему можно получить доступ |
| 2 | База данных | Высокая для чтения, ограниченная для записи | Чтение данных; запись только с разрешения владельца системы и если она не обходит бизнес-логику приложения |
| 3 | Файлы и почта (выгрузки, обмен) | Средняя: зависит от формата и расписания выгрузки | Система умеет выгружать и загружать данные в файлы |
| 4 | UI (web, desktop) | Низкая | Других каналов нет или их получение займет несоразмерно много времени |

**Правила:**
- Выбор канала для каждой системы фиксируется в ТП с обоснованием
- Если выбран UI, хотя API существует, в ТП указывается причина (нет доступа, нет нужного метода, сроки)
- Не записывайте данные напрямую в таблицы чужой системы, если это обходит ее проверки и бизнес-логику
- Каналы можно комбинировать: чтение через БД, создание документа через UI

## INTEGRATION-05. Выполняйте HTTP-запросы через HttpClient

🟡 **Рекомендуется**

Для запросов к REST API используйте `HttpClient` (или HTTP-активности PIX RPA, если их возможностей достаточно). Не используйте устаревшие `WebClient` и `HttpWebRequest`: Microsoft не рекомендует их для новой разработки.

**Правила:**
- **Создавайте клиент один раз** на запуск робота ([INTEGRATION-03](#integration-03-создавайте-httpclient-один-раз-на-запуск-робота))
- **Задавайте таймаут** явно (см. [INTEGRATION-01](#integration-01-задавайте-таймауты-для-всех-внешних-вызовов))
- **Проверяйте код ответа** и различайте ошибки: `4xx` обычно означает ошибку в данных или доступе (бизнес-исключение или ошибка конфигурации), `5xx` и таймауты означают техническое исключение с повтором (см. [ERROR-03](../2-develop/error.md#error-03-разделяйте-бизнес-исключения-и-технические-исключения))
- **Не собирайте URL конкатенацией** с пользовательскими данными: кодируйте параметры через `Uri.EscapeDataString`
- **Базовый адрес и учетные данные.** В ассетах; токены не логируются (см. [LOG-02](../2-develop/log.md#log-02-не-логируйте-конфиденциальные-данные))

```csharp
// Init: один клиент на весь запуск робота
var httpClient = new HttpClient
{
    BaseAddress = new Uri(apiBaseUrl),
    Timeout = TimeSpan.FromSeconds(apiTimeoutSeconds)
};
httpClient.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", apiToken);

// Process Transaction: запрос и проверка ответа
var response = httpClient.GetAsync($"customers/{Uri.EscapeDataString(customerId)}").Result;

if (response.StatusCode == HttpStatusCode.NotFound)
{
    var notFound = new InvalidOperationException($"Клиент {customerId} не найден в CRM");
    notFound.Data["ExceptionType"] = "Business";
    throw notFound;
}

response.EnsureSuccessStatusCode(); // 5xx и прочие ошибки — техническое исключение
var customerJson = response.Content.ReadAsStringAsync().Result;

// End Process
httpClient.Dispose();
```
