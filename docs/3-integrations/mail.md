# Работа с почтой

Почта — частый источник транзакций (письма с заявками, счетами, выписками) и канал уведомлений. Правила этого раздела нужны, чтобы робот не зависел от настольного почтового клиента и не терял и не дублировал письма.

## MAIL-01. Работайте с почтой по протоколам, а не через Outlook

🔴 **Обязательно**

Не используйте Outlook через COM (`Microsoft.Office.Interop.Outlook`) и активности, которые управляют приложением Outlook. Подключайтесь к почтовому серверу напрямую по протоколу.

| Сервер | Протокол | Как подключаться |
|--------|----------|------------------|
| Любой почтовый сервер | IMAP — чтение, SMTP — отправка | Активности PIX RPA для IMAP/SMTP или библиотека [MailKit](https://github.com/jstedfast/MailKit) |
| Microsoft Exchange (локальный) | EWS (Exchange Web Services) | Активности PIX RPA для Exchange или библиотека `Microsoft.Exchange.WebServices` |
| Microsoft 365 / Exchange Online | Microsoft Graph API | Активностей для Graph в PIX RPA нет — REST-запросы через `HttpClient` (см. [INTEGRATION-04](integration.md#integration-04-выполняйте-http-запросы-через-httpclient)) |

> [!WARNING]
> Microsoft отключает EWS в Exchange Online. Для облачной почты Microsoft 365 используйте Microsoft Graph; EWS остается вариантом для локального Exchange Server.

**Проблемы Outlook через COM:**
- Нужен установленный Outlook с настроенным профилем под учетной записью робота
- Окна безопасности («Программа пытается получить доступ к адресам электронной почты») блокируют робота
- Outlook зависает при синхронизации больших ящиков и не работает без интерактивной сессии
- Зависшие процессы `OUTLOOK.EXE` мешают следующему запуску

> [!NOTE]
> `System.Net.Mail.SmtpClient` Microsoft не рекомендует для новой разработки. Для отправки по SMTP используйте активности PIX RPA или MailKit.

## MAIL-02. Используйте отдельный почтовый ящик робота

🔴 **Обязательно**

- Робот читает и отправляет письма из выделенного ящика (или общего ящика процесса), а не из ящика сотрудника
- Учетные данные ящика хранятся в ассете типа «Учетные данные» (см. [CONFIG-02](../1-project/config.md#config-02-используйте-зашифрованные-ассеты-для-хранения-конфиденциальных-данных))
- Адреса сервера, порты, имена папок — в ассетах (см. [CONFIG-05](../1-project/config.md#config-05-не-используйте-жесткое-кодирование))

## MAIL-03. Отмечайте обработанные письма явно

🔴 **Обязательно**

Признак «непрочитано» ненадежен: письмо может прочитать человек, почтовый клиент или другой робот. Используйте явную отметку:

- перемещайте письмо в папку `Processed` / `Failed` после обработки транзакции
- или ставьте категорию / флаг, если перемещение невозможно

Письмо перемещается **после** того, как транзакция создана в очереди или обработана, — по тому же принципу, что обновление статуса очереди (см. [QUEUE-02](queue.md#queue-02-обрабатывайте-элемент-очереди-как-транзакцию)). Для повторной загрузки используйте идентификатор письма (`Message-ID`) как ключ идемпотентности (см. [RECOVERY-01](../2-develop/recovery.md#recovery-01-делайте-обработку-транзакции-идемпотентной)).

## MAIL-04. Проверяйте входящие письма и вложения

🟡 **Рекомендуется**

- Обрабатывайте письма только от ожидаемых отправителей или доменов; остальные перемещайте в отдельную папку для ручного разбора
- Проверяйте тип и размер вложений до обработки; не запускайте исполняемые файлы и макросы из вложений
- Сохраняйте вложения во временную папку с уникальными именами (см. [FILE-02](../2-develop/file.md#file-02-управляйте-временными-файлами))
- Не полагайтесь на тему письма как на единственный признак типа документа: пользователи ее меняют
