# Оценка процесса

Не каждый процесс стоит автоматизировать с помощью RPA. Робот, построенный на нестабильном процессе или нестабильном интерфейсе, будет требовать постоянной доработки и в итоге обойдется дороже ручного труда. Оценка до начала разработки дешевле, чем переделка после запуска.

## ASM-01. Оценивайте пригодность процесса до начала разработки

**Уровень:** MUST — обязательно

Перед проектированием бизнес-аналитик заполняет чек-лист пригодности. Результат оценки прикладывается к задаче на автоматизацию.

| Критерий | Хорошо для RPA | Плохо для RPA |
|----------|----------------|---------------|
| Правила | Четкие, формализуемые правила | Решения «на глаз», экспертная оценка |
| Входные данные | Структурированные или типовые документы | Свободный текст, рукописный ввод, разные форматы у каждого контрагента |
| Стабильность процесса | Процесс не менялся полгода и не планируется менять | Процесс перестраивается, идет внедрение новой системы |
| Стабильность систем | Интерфейсы и API меняются редко | Частые обновления интерфейса, запланирована замена системы |
| Объем | Много однотипных операций | Несколько операций в месяц |
| Доля исключений | Большинство случаев проходит по основному сценарию | Каждый второй случай нестандартный |
| Доступы | Можно выдать роботу отдельную учетную запись | Доступ только по личной учетной записи, двухфакторная аутентификация без технической альтернативы |

**Когда стоит остановиться или пересмотреть подход:**
- Целевая система будет заменена в ближайшие месяцы — дождитесь замены
- Есть API или штатная интеграция — возможно, нужна интеграция, а не робот (см. [INT-01](../02-guidelines/integrations.md#int-01-выбирайте-канал-интеграции-по-надежности-api--бд--файлы--ui))
- Процесс неоптимален — сначала упростите процесс, затем автоматизируйте

## ASM-02. Оценивайте эффект автоматизации

**Уровень:** SHOULD — рекомендуется

Решение об автоматизации принимается на основе сравнения затрат и эффекта. Оценка фиксируется в задаче и пересматривается после запуска.

**Эффект:**
- Высвобождаемое время: объем операций × время на операцию × доля операций, которые робот обработает без человека
- Снижение ошибок, штрафов, просрочек
- Ускорение процесса (обработка ночью, в выходные)

**Затраты:**
- Разработка и тестирование
- Поддержка: ориентировочно 15–25% от затрат на разработку в год, для UI-автоматизации — выше
- Лицензии и инфраструктура (машины для роботов, внешние сервисы)

**После запуска** сравните фактические показатели с оценкой: объем, долю автоматической обработки, число инцидентов. Это делает следующие оценки точнее.
