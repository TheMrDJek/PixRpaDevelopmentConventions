# Релиз и развертывание

Релиз переносит проверенную версию робота на контур PROD. Цель правил этого раздела — чтобы в проде всегда работала известная, протестированная версия, а при проблеме можно было быстро вернуться к предыдущей. Работа с ветками и тегами описана в [Соглашениях о Git](../01-conventions/git.md).

## DPL-01. Версионируйте роботов по SemVer

**Уровень:** MUST — обязательно

Каждая версия робота, которая уходит на UAT или PROD, имеет номер `MAJOR.MINOR.PATCH`:

| Часть | Когда увеличивать | Пример |
|-------|-------------------|--------|
| MAJOR | Несовместимые изменения: новый формат элемента очереди, новые обязательные ассеты, изменение входных параметров | `1.4.2` → `2.0.0` |
| MINOR | Новая функциональность без нарушения совместимости | `1.4.2` → `1.5.0` |
| PATCH | Исправление ошибок | `1.4.2` → `1.4.3` |

Одна и та же версия имеет одинаковый номер в теге Git (см. [GIT-07](../01-conventions/git.md#git-07-используйте-тегирование-для-версий)), в CHANGELOG и в PIX Master.

## DPL-02. Продвигайте одну и ту же сборку по контурам DEV → UAT → PROD

**Уровень:** MUST — обязательно

На PROD выпускается ровно та версия, которая прошла тестирование на UAT. Нельзя «чуть-чуть поправить» робота между UAT и PROD: любое изменение — новая версия и новый прогон тестов.

- Отличия между контурами задаются только ассетами (см. [CFG-01](../01-conventions/config-and-secrets.md#cfg-01-используйте-ассеты-мастера-для-хранения-конфигурации)), а не правками кода
- Изменения на PROD вносятся только через релиз; правка робота напрямую в PROD запрещена
- Хотфикс проходит тот же путь, только быстрее: ветка `hotfix`, ревью, проверка на UAT, релиз

## DPL-03. Готовьте релиз по чек-листу

**Уровень:** SHOULD — рекомендуется

- [ ] Выполнены условия Definition of Done (см. [DSN-03](design.md#dsn-03-проверяйте-готовность-задачи-к-разработке))
- [ ] Новые и измененные ассеты созданы на PROD до публикации версии
- [ ] Обновлены CHANGELOG и runbook
- [ ] Согласовано окно релиза с владельцем процесса
- [ ] Определено, что делать с элементами очереди, которые уже есть (обработать старой версией, дождаться опустошения, перезалить)
- [ ] Робот остановлен штатно (см. [REL-06](../01-conventions/reliability.md#rel-06-проверяйте-сигнал-остановки-от-мастера)), текущие транзакции завершены
- [ ] Подготовлен план отката

## DPL-04. Имейте план отката для каждого релиза

**Уровень:** MUST — обязательно

До релиза известно, как вернуть предыдущую версию и сколько это займет.

- Предыдущая версия робота остается доступной в PIX Master или в репозитории по тегу
- Если релиз меняет ассеты, сохраните их прежние значения
- Если релиз меняет формат данных (очередь, таблицы БД), продумайте, как старая версия будет работать с данными, созданными новой
- После релиза проверьте первые транзакции; при ошибках откатывайтесь сразу, а не исправляйте в проде
