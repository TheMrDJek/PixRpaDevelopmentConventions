# Персональные данные

Роботы часто обрабатывают персональные данные: ФИО, паспортные данные, телефоны, адреса, СНИЛС, данные о здоровье. Обработка персональных данных в России регулируется Федеральным законом № 152-ФЗ «О персональных данных», а также внутренними политиками компании. Робот обрабатывает их так же, как сотрудник, и подчиняется тем же требованиям.

Раздел не заменяет консультацию службы информационной безопасности. Если робот обрабатывает персональные данные, согласуйте его с ИБ на этапе проектирования.

## PRIVACY-01. Обрабатывайте только необходимые персональные данные

🔴 **Обязательно**

Робот получает, хранит и передает только те персональные данные, которые нужны для выполнения процесса.

- Не кладите в элемент очереди всю строку из исходной системы, если для обработки нужны два поля
- Не выгружайте полную таблицу клиентов ради поиска одного клиента, фильтруйте в запросе (см. [DB-02](../3-integrations/db.md#db-02-выполняйте-фильтрацию-в-sql-запросах-а-не-в-коде))
- Не сохраняйте промежуточные файлы с персональными данными дольше, чем идет обработка транзакции

## PRIVACY-02. Не допускайте персональные данные в логи, статусы и имена файлов

🔴 **Обязательно**

Логи, статусы элементов очереди и имена файлов видит широкий круг людей: поддержка, администраторы, разработчики. Персональные данные туда не попадают.

| Место | Неправильно | Правильно |
|-------|-------------|-----------|
| Лог | `Обработан клиент Иванов Иван, паспорт 4510 123456` | `[Q-10452] Обработан клиент ID 88213` |
| Статус элемента очереди | `Ошибка: не найден Петров П.П.` | `Ошибка: клиент не найден в CRM (ID 88213)` |
| Имя файла | `Заявление_Иванов_И_И.pdf` | `Заявление_88213.pdf` |
| Текст исключения | `Неверный СНИЛС 123-456-789 00` | `Неверный формат СНИЛС` |

Способы маскирования описаны в [LOG-06](log.md#log-06-не-логируйте-конфиденциальные-данные).

## PRIVACY-03. Ограничивайте доступ к скриншотам и артефактам с персональными данными

🔴 **Обязательно**

Скриншоты ошибок, выгрузки, временные и отладочные файлы могут содержать персональные данные, даже если робот не записывает их явно.

- Храните такие артефакты в папках с доступом только для робота и поддержки
- Задайте срок хранения и автоматическое удаление (например, 30 дней для скриншотов ошибок)
- Не пересылайте скриншоты с персональными данными в чаты и письма; передавайте ссылку на защищенное хранилище
- Если скриншот не нужен для разбора, не делайте его

## PRIVACY-04. Используйте обезличенные данные для разработки и тестирования

🔴 **Обязательно**

На контурах DEV и UAT используйте синтетические или обезличенные данные. Копирование продуктивных персональных данных на контуры DEV и UAT допустимо только по согласованию с ИБ.

- Тестовые файлы и выгрузки в репозитории не содержат реальных персональных данных (см. [CONFIG-04](../1-project/config.md#config-04-не-коммитьте-конфиденциальные-данные))
- Для отладки продуктивной ошибки воспроизводите ее на обезличенной копии данных, а не на рабочем контуре с отладчиком

[⬆ К содержанию](#содержание)

## PRIVACY-05. Не передавайте персональные данные во внешние сервисы без согласования

🔴 **Обязательно**

Отправляя данные во внешний сервис, робот передает их третьему лицу. Это относится к облачному OCR, сервисам перевода, внешним API и особенно к LLM-сервисам (см. [ИИ и распознавание документов](ai.md)).

- Передача персональных данных во внешний сервис согласуется с ИБ и фиксируется в ТП робота
- Если сервис можно развернуть внутри контура компании, предпочитайте внутренний вариант
- Если согласования нет, перед отправкой удаляйте или заменяйте персональные данные
