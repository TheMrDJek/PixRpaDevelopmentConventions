# Ассеты

Ассеты в PIX Master используются для централизованного хранения конфигурационных данных и учетных данных. Правильное управление ассетами критически важно для безопасности и гибкости решений. Как робот использует ассеты, описано в разделе [Конфигурация и конфиденциальные данные](../01-conventions/config-and-secrets.md).

## AST-01. Именуйте ассеты по типу

**Уровень:** MUST — обязательно

- **Учетные данные:** `Cred_{Система}_{Назначение}`
  - Примеры: `Cred_SAP_ReadOnly`, `Cred_Sharepoint_Admin`
- **Значения:** `Param_{Проект}_{Категория}_{Название}`
  - Примеры: `Param_AP_Email_SupportAddress`, `Param_Common_API_BaseURL`
- **Коллекции:** `Config_{Проект}_{Назначение}`
  - Примеры: `Config_FinanceBot_EmailTemplates`, `Config_HRBot_ValidationRules`

Имя ассета одинаково на всех контурах, различаются только значения.

## AST-02. Организуйте ассеты по проектам

**Уровень:** SHOULD — рекомендуется

- Группируйте ассеты по проектам или функциональным областям
- Создайте иерархию папок для удобной навигации
- Используйте теги для дополнительной категоризации

**Типы ассетов и их применение:**
- **Строки подключения** (Connection Strings) — для доступа к базам данных; храните как защищенные данные, если содержат пароль
- **Учетные данные** (Credentials) — для аутентификации в системах
- **URL и эндпоинты API** — для интеграций с внешними системами
- **Настройки email** — для отправки уведомлений и отчетов
- **Пути к файлам** — локальные и сетевые пути для хранения данных
- **Бизнес-правила** — параметры для логики обработки

## AST-03. Ограничивайте доступ к учетным данным

**Уровень:** MUST — обязательно

- Ограничьте доступ к учетным данным только необходимым пользователям/процессам
- Регулярно обновляйте пароли и секреты
- Не храните конфиденциальные данные в текстовом виде
- Используйте шифрование для чувствительной информации (см. [CFG-02](../01-conventions/config-and-secrets.md#cfg-02-используйте-зашифрованные-ассеты-для-хранения-конфиденциальных-данных))

## AST-04. Ведите каталог ассетов

**Уровень:** SHOULD — рекомендуется

- Создайте каталог всех ассетов с описанием назначения и зависимостей (какие роботы используют ассет)
- Фиксируйте изменения в ассетах в системе контроля версий (список ассетов и их назначение — в SDD робота; значения секретов в репозиторий не попадают)
- Регулярно проверяйте актуальность и используемость ассетов
- Сохраняйте прежние значения ассетов перед внесением существенных изменений

**Связь с очередями и задачами:**
- **Очереди данных:** используйте ассеты для хранения строк подключения и параметров обработки
- **Задачи и триггеры:** используйте ассеты для порогов и условий активации
- **Роботы:** храните все конфигурационные параметры в ассетах, а не в коде роботов
