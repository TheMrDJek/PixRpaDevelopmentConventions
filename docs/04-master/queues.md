# Очереди данных

Очереди данных (Data Queues) в PIX Master используются для хранения транзакций и обмена данными между роботами. Правильная организация очередей критически важна для эффективного управления процессами. Работа с очередями из кода робота описана в [Соглашении об очередях](../01-conventions/queues.md).

## MQ-01. Именуйте очереди по формату {Проект}_{ТипДанных}_{Назначение}

**Уровень:** MUST — обязательно

- Используйте формат: `{Проект}_{ТипДанных}_{Назначение}`
- Примеры:
  - `AP_Invoices_Processing` — очередь счетов для обработки в проекте Accounts Payable
  - `HR_Employees_Validation` — очередь данных сотрудников для валидации в HR-проекте
  - `Sales_Orders_Confirmation` — очередь заказов для подтверждения в проекте Sales

Если процесс построен по схеме Dispatcher/Performer (см. [PRJ-06](../01-conventions/project-structure.md#prj-06-разделяйте-загрузку-и-обработку-транзакций-dispatcher--performer)), очередь между ними называется по сущности, которую она содержит, а не по роботу: `AP_Invoices_Processing`, а не `AP_Dispatcher_Queue`.

## MQ-02. Разделяйте очереди по назначению

**Уровень:** SHOULD — рекомендуется

- **Транзакционные очереди** — для основных бизнес-данных, обрабатываемых роботами
  - `{Проект}_{Сущность}_{Статус}`: `Finance_Invoices_New`, `Finance_Invoices_Failed`
- **Служебные очереди** — для внутреннего взаимодействия роботов
  - `{Проект}_Service_{Назначение}`: `Common_Service_Notifications`
- **Архивные очереди** — для хранения исторических данных
  - `{Проект}_{Сущность}_Archive_{Период}`: `Finance_Invoices_Archive_2023Q2`

## MQ-03. Используйте единую шкалу приоритетов

**Уровень:** SHOULD — рекомендуется

- Используйте стандартные приоритеты (1–10) для всех очередей
- Документируйте логику приоритизации для каждого проекта
- Придерживайтесь следующих рекомендаций:
  - 1–3: высокий приоритет (критические транзакции)
  - 4–7: средний приоритет (стандартные транзакции)
  - 8–10: низкий приоритет (некритичные или архивные транзакции)

## MQ-04. Документируйте структуру данных очереди

**Уровень:** MUST — обязательно

- Придерживайтесь единой структуры данных для схожих процессов
- Документируйте схему данных для каждой очереди (в SDD робота, см. [DSN-02](../03-robot-lifecycle/design.md#dsn-02-описывайте-техническое-решение-в-sdd))
- Минимизируйте количество полей, используйте только необходимые (см. также [PD-01](../01-conventions/personal-data.md#pd-01-обрабатывайте-только-необходимые-персональные-данные))
- Формат данных элемента выбирайте по [QUE-01](../01-conventions/queues.md#que-01-выбирайте-оптимальный-формат-данных-для-элементов-очереди); сложные вложенные структуры в одном поле допустимы, только если их нельзя разложить на поля
