# Мониторинг и оповещения

Цель мониторинга — узнать о проблеме раньше бизнес-пользователя. Оповещения должны приходить тем, кто может отреагировать, и только по событиям, которые требуют реакции: если оповещений слишком много, их перестают читать.

## MON-01. Настройте оповещения о событиях, требующих реакции

**Уровень:** MUST — обязательно

Минимальный набор оповещений для продуктивного контура:

| Событие | Кому | Пример причины |
|---------|------|----------------|
| Робот завершился с ошибкой или остановился по порогу системных ошибок (см. [REL-05](../01-conventions/reliability.md#rel-05-останавливайте-робота-после-серии-системных-исключений-подряд)) | Поддержка L1 | Недоступна целевая система, истек пароль |
| Задача не запустилась по расписанию | Поддержка L1 | Хост недоступен, занят другим роботом |
| Хост недоступен | Администратор | Сбой сервера, сетевые проблемы |
| Очередь не обрабатывается дольше SLA | Поддержка L1, владелец процесса | Робот не запущен, обработка идет слишком медленно |
| Доля бизнес-исключений выше обычной | Владелец процесса | Изменились входные данные |

Каждое оповещение содержит ссылку на runbook робота (см. [SUP-02](../03-robot-lifecycle/support.md#sup-02-готовьте-runbook-для-поддержки)).

## MON-02. Отслеживайте загрузку и состояние инфраструктуры

**Уровень:** SHOULD — рекомендуется

- Настройте оповещения о недоступности хостов
- Создайте дашборды для мониторинга загрузки ресурсов
- Регулярно анализируйте производительность и масштабируйте при необходимости
- Отслеживайте свободное место на дисках хостов: временные файлы и логи роботов могут заполнить диск

## MON-03. Проверяйте оповещения

**Уровень:** SHOULD — рекомендуется

Оповещение, которое не срабатывает, хуже отсутствия оповещения: команда считает, что все под контролем. После настройки и после изменений в инфраструктуре оповещений проверяйте их на контуре UAT: остановите хост, сломайте ассет, заполните очередь.
