# Агенты роботов

Агенты роботов в PIX Master — это компоненты, выполняющие задачи автоматизации. Существуют два основных типа: Unattended (работающие без участия человека) и Attended (требующие взаимодействия с пользователями).

## AGT-01. Именуйте агентов по типу робота

**Уровень:** MUST — обязательно

- **Unattended-роботы:** `{Проект}_{Процесс}_Bot{Номер}`
  - Примеры: `AP_InvoiceProcessing_Bot01`, `HR_Onboarding_Bot02`
- **Attended-роботы:** `{Департамент}_{РабочееМесто}_{ТипАссистента}`
  - Примеры: `Finance_AccountManager_Assistant`, `HR_Recruiter_Helper`

Для процессов по схеме Dispatcher/Performer (см. [PRJ-06](../01-conventions/project-structure.md#prj-06-разделяйте-загрузку-и-обработку-транзакций-dispatcher--performer)) роль указывается в имени процесса: `AP_InvoiceDispatcher_Bot01`, `AP_InvoicePerformer_Bot01`.

## AGT-02. Учитывайте различия в настройке Unattended и Attended роботов

**Уровень:** SHOULD — рекомендуется

| Параметр | Unattended | Attended |
|----------|------------|----------|
| Запуск | Автоматический по расписанию/триггеру | Ручной пользователем |
| Выполнение | На выделенных серверах | На рабочих станциях пользователей |
| Интерфейс | Часто не требуется (headless) | Взаимодействие с пользователем |
| Логирование | Детальное | Базовое |
| Обработка ошибок | Автоматическая + эскалация | С участием пользователя |

## AGT-03. Группируйте роботов по проектам

**Уровень:** SHOULD — рекомендуется

- Создавайте отдельные папки для каждого проекта/департамента
- Группируйте связанных роботов в одну логическую группу
- Используйте теги для дополнительной классификации

## AGT-04. Выдавайте роботам отдельные технические учетные записи

**Уровень:** MUST — обязательно

- Каждый Unattended-робот работает под собственной технической учетной записью Windows и собственными учетными записями в целевых системах (см. [INT-03](../02-guidelines/integrations.md#int-03-используйте-отдельные-учетные-записи-робота-для-каждой-системы))
- Учетная запись имеет минимальные права, необходимые процессу
- Для учетных записей определены владелец (ответственный сотрудник) и срок смены пароля
- Смена пароля выполняется через обновление ассета «Учетные данные», без изменения робота; перед сменой проверьте, какие роботы используют ассет
- При выводе робота из эксплуатации учетные записи блокируются (см. [SUP-05](../03-robot-lifecycle/support.md#sup-05-выводите-роботов-из-эксплуатации-по-плану))

## AGT-05. Публикуйте версии роботов с номером SemVer

**Уровень:** MUST — обязательно

- Публикуйте версии с семантическим версионированием (`v1.2.3`), см. [DPL-01](../03-robot-lifecycle/release-and-deploy.md#dpl-01-версионируйте-роботов-по-semver)
- Документируйте изменения в каждой версии
- Поддерживайте историю предыдущих версий, чтобы можно было выполнить откат (см. [DPL-04](../03-robot-lifecycle/release-and-deploy.md#dpl-04-имейте-план-отката-для-каждого-релиза))

## AGT-06. Настраивайте лимиты параллельного выполнения

**Уровень:** SHOULD — рекомендуется

- Установите оптимальные лимиты параллельного выполнения
- Настройте приоритеты выполнения для разных типов роботов
- Отслеживайте загрузку системы и регулируйте параметры при необходимости
- Запускайте несколько экземпляров Performer'а на одной очереди, только если обработка транзакций идемпотентна (см. [REL-01](../01-conventions/reliability.md#rel-01-делайте-обработку-транзакции-идемпотентной)) и целевые системы выдерживают параллельную нагрузку
