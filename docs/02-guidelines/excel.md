# Работа с Excel

Excel-файлы — самый частый источник и приемник данных для роботов. От способа работы с ними зависит скорость робота и то, сколько «зависших» процессов Excel будет оставаться на машине.

## XLS-01. Не используйте Excel Interop и COM

**Уровень:** MUST — обязательно

Не работайте с Excel-файлами через `Microsoft.Office.Interop.Excel`, COM-объекты (`Excel.Application`) и активности, которые запускают приложение Excel. Используйте активности PIX RPA для работы с файлами Excel без запуска приложения или библиотеки, которые читают и пишут файл напрямую.

**Проблемы Interop в роботах:**
- **Нужен установленный и лицензированный Excel** на каждой машине робота
- **Зависшие процессы `EXCEL.EXE`.** Если скрипт упал до вызова `Quit()` и освобождения всех COM-объектов, процесс остается в памяти, держит файл заблокированным и копится от запуска к запуску
- **Модальные окна.** Предупреждения о макросах, защищенном просмотре, восстановлении файла блокируют робота до таймаута
- **Зависимость от сессии и окружения.** Interop плохо работает без интерактивной сессии пользователя; Microsoft не поддерживает серверную автоматизацию Office
- **Скорость.** Каждое обращение к ячейке — межпроцессный вызов; чтение большого листа по ячейкам занимает минуты

**Чем заменить:**

| Задача | Вариант |
|--------|---------|
| Чтение и запись таблиц | Активности PIX RPA для Excel-файлов, не требующие запуска Excel; библиотеки [ClosedXML](https://github.com/ClosedXML/ClosedXML), [NPOI](https://github.com/nissl-lab/npoi) |
| Быстрое чтение больших файлов | [ExcelDataReader](https://github.com/ExcelDataReader/ExcelDataReader) — только чтение, поддерживает `.xls` и `.xlsx` |
| Формирование отчетов по шаблону | Шаблон в проекте робота (см. [PRJ-04](../01-conventions/project-structure.md#prj-04-храните-шаблоны-и-прочие-файлы-в-самом-проекте-робота)) + ClosedXML / активности PIX RPA |
| CSV | Чтение как текста, без Excel |

> [!WARNING]
> У библиотеки EPPlus начиная с версии 5 коммерческая лицензия. Перед использованием EPPlus в роботах согласуйте лицензию или выберите ClosedXML / NPOI.

## XLS-02. Используйте приложение Excel только там, где без него нельзя

**Уровень:** MAY — допустимо

Запуск приложения Excel оправдан, только если задача требует движка Excel:

- выполнение макросов VBA, которые нельзя переписать
- пересчет формул с внешними связями или надстройками
- обновление сводных таблиц и подключений к внешним данным
- экспорт в PDF с сохранением форматирования Excel

В этих случаях:
- изолируйте работу с Excel в одном скрипте слоя Infrastructure
- гарантированно закрывайте приложение в `finally` и в состоянии End Process
- перед запуском и после завершения проверяйте, не осталось ли процессов `EXCEL.EXE`, запущенных под учетной записью робота
- укажите причину использования Excel в SDD

## XLS-03. Читайте лист целиком, а не по ячейкам

**Уровень:** SHOULD — рекомендуется

Загружайте диапазон или лист в `DataTable` одним вызовом и дальше обрабатывайте данные в памяти (см. [LINQ](linq.md)). Обращение к ячейкам в цикле многократно медленнее и усложняет код.

Аналогично для записи: сформируйте `DataTable` и запишите его в лист одной операцией.

## XLS-04. Обращайтесь к столбцам по заголовкам

**Уровень:** SHOULD — рекомендуется

Пользователи добавляют и переставляют столбцы в Excel-файлах. Обращение к столбцу по букве (`"C"`) или индексу ломает робота при первой такой правке (см. [HC-01](hardcoding.md#hc-01-не-используйте-жесткое-кодирование)).

- Находите столбцы по тексту заголовка
- При чтении проверяйте, что все ожидаемые заголовки на месте; если нет — бизнес-исключение с перечнем отсутствующих столбцов
- Если файл без заголовков, используйте именованные константы для индексов
