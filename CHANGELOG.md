- Раздел «Схемы» в CONTRIBUTING: схемы рисуются в SVG с PNG рядом, единые цвета для типов блоков, легенда на каждой схеме
- `tools/render_svg.py`: пересобирает PNG схем из SVG через headless Chrome или Edge
- QUEUE-09: задавайте элементу очереди уникальную ссылку
- QUEUE-10: отмечайте в элементе очереди выполненные необратимые шаги
- QUEUE-11: ограничивайте время элемента в статусах New и Processing
- QUEUE-12: запускайте обработку очереди по событию и подстраховывайте процессом

- Правила стиля текста в CONTRIBUTING на основе stop-slop
- Указана целевая версия: соглашения написаны для PIX Studio 3.2.1 и выше (.NET 10)
- Правило оформления примеров: скриншоты из PIX Studio вместо C#-вставок, чтобы новым коллегам было понятно, как правило выглядит в Studio (CONTRIBUTING)

### Изменено
- Все документы пройдены по навыку stop-slop: тире вне определений заменены перестройкой фраз (223 → 6), вступления разделов из общих слов («ключевой аспект», «мощный инструмент») заменены описанием того, о чем раздел, 25 списков «Преимущества / Последствия несоблюдения» заменены строкой «Почему» с конкретикой. Из README убрана ссылка на внешний репозиторий шаблонов
- В содержании файлов уровень правила пишется в скобках «(🔴 Обязательно)» вместо «— 🔴 Обязательно»; в project.md и template.md убраны лишние тире
- Создание проекта разделено на два файла. `project.md` «Проект робота» (PROJECT) — правила для любого робота: PROJECT-01 «Выбирайте шаблон по типу процесса» (было PROJECT-02 «Используйте шаблон на основе State Machine»: заголовок обещал State Machine всегда, хотя есть исключения; справочный раздел «Тип процесса» вошел в правило), PROJECT-02 ресурсы робота в проекте (было PROJECT-04, «шаблоны и прочие файлы»: слово «шаблон» занято шаблоном проекта, а «ассет» — PIX Master), PROJECT-03 версионированная библиотека (было PROJECT-05). Новый `template.md` «Шаблон на State Machine» (TEMPLATE): TEMPLATE-01 слои (было PROJECT-01), TEMPLATE-02 состояния (было PROJECT-03). Якоря изменились, ссылки в репозитории обновлены
- Dispatcher / Performer (было PROJECT-06) и Transaction Script (было PROJECT-07) стали справочными разделами без уровня: это архитектурные подходы, а не требования
- PROJECT-02: описано, что считать ресурсом робота (небольшой файл, который меняется вместе с логикой робота) и что нет (входные и выходные файлы, файлы, которые меняет бизнес, большие файлы); робот не меняет ресурс, а копирует его перед заполнением; «Почему» расширено: нет зависимости от сетевой папки и прав учетной записи, файл не окажется занят, шаблон не поменяют втихую
- PROJECT-01: добавлены «Что дает State Machine» (6 пунктов) и «Чем State Machine неудобен» (6 пунктов, в том числе мнения сообщества о REFramework: тяжеловат для маленьких процессов, без понимания шаблона робот получается хуже, отладка между файлами). TEMPLATE-02: шаблон задает базовые переменные `main.pix`, остальные робот добавляет сам
- Типов процесса два: линейный и транзакционный. Итеративный тип убран: в RPA так называют перебор списка в цикле без статуса у каждого элемента, а это транзакционный процесс, сделанный хуже. Процессы с зависимыми элементами (проводка по порядку) описаны оговоркой к транзакционному: элементы строго по порядку, остановка на первой ошибке, без нескольких обработчиков. State Machine нужен любому процессу: линейному хватает трех состояний (Init → Process Transaction → End Process), PROJECT-01 стал обязательным для всех роботов, кроме Attended-робота на одно действие, утилиты и прототипа. В TEMPLATE-02 указано, что схему из четырех состояний в RPA называют REFramework
- Шаблон на State Machine описан на одном сквозном примере, роботе заказов `Orders.ProcessOrderRequest`: схема архитектуры (слои, адаптеры `Infrastructure`, внешние системы, PIX Master как внешняя система), таблицы «что лежит и кого может вызывать» и «куда положить общий скрипт». Шаблон работает и без PIX Master
- TEMPLATE-02: `main.pix` как State Machine — блоки состояния и `Route`, переходы через `GoToStep` вместо бесконечного цикла, схема и таблица переходов, три уровня повторов, стандартные переменные `main.pix`. End Process живет в блоке `main.pix`, отдельная папка не обязательна
- Сценарий транзакции: схема `AddOrderItem` вместо текстовых примеров, у каждой операции своя папка, общие шаги — в `Transactions/Shared`
- В примерах имена без `_`, точка разделяет контекст: `Orders.ProcessOrderRequest`, `Mail.Dispatcher`. Убраны ссылки на внешний репозиторий шаблонов, из слоя Tests убраны E2E-тесты (они идут на UAT)
- NAMING-02: дерево папок заменено ссылкой на TEMPLATE-01, добавлены папка `Shared` и необязательная папка End Process
- Схемы mermaid в project.md и master.md («Связь между компонентами») заменены картинками; подписи на линиях с белой подложкой
- ERROR-06: главное отличие бизнес-исключения от системного вынесено в начало, добавлены примеры в четырех процессах и тест «повтор через 10 минут»
- CONFIG-01: список типов ассетов исправлен по PIX Master (пять типов, JSON хранится в строке)
