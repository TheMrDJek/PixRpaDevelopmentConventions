## [2.0.0] - дата выпуска будет указана при слиянии в master

### Изменено
- README разбит на отдельные файлы в `docs/`, разделы упорядочены по пути разработчика: создание проекта → разработка → интеграции → публикация и работа в PIX Master
- Репозиторий сосредоточен на правилах для разработчиков. Правила написания C#-кода и скриптов PIX объединены в разделе «Разработка»: код и активности, переменные, условия, циклы, строки, LINQ, файлы. Именование разделено на именование проекта (папки, скрипты, файлы) и имена параметров и переменных. Git, код-ревью, жизненный цикл робота, документирование и администрирование PIX Master убраны из соглашений
- У каждого правила есть тег, совпадающий с именем файла (`ERROR-03` — третье правило в `error.md`), и уровень: 🔴 Обязательно, 🟡 Рекомендуется, 🟢 По ситуации
- Блоки `<details>` заменены на заголовки, в каждый файл добавлено содержание
- Объединены дублирующиеся разделы: условия, работа с файлами, очереди; жесткое кодирование и именование ассетов перенесены в конфигурацию
- Крупные рекомендации разбиты на отдельные правила
- Правило об общих библиотеках заменено правилом о версионированных библиотеках (PROJECT-05)
- Примечания оформлены как GitHub alerts (#34)
- Картинки перенесены из `common/` в `images/<раздел>/`

### Добавлено
- Работа робота в PIX Master: именование роботов, очередей, задач и ассетов, триггеры, связь компонентов (#28)
- Публикация: SemVer, перенос между контурами, откат (PUBLISH)
- Тестирование (TEST, #6)
- Надежность: идемпотентность, восстановление, остановка после серии ошибок (RECOVERY)
- Персональные данные и 152-ФЗ (PRIVACY)
- Интеграции: выбор канала, таймауты, учетные записи, HttpClient (INTEGRATION, #11)
- Excel без Interop (EXCEL), почта по SMTP/IMAP/Exchange (MAIL)
- ИИ и интеллектуальная обработка документов (AI)
- Бизнес- и системные исключения (ERROR-06), источник исключения (ERROR-07, #43)
- Параметризованные SQL-запросы (DB-05), ID транзакции в логах (LOG-07)
- Входные параметры робота (CONFIG-03, #25)
- «Цикл с … по» для ожидания UI (LOOP-02, #40), «Цикл для каждого» (LOOP-03, #27)
- Типы процессов, недостатки State Machine (#37, #38), Dispatcher/Performer и доменный формат (PROJECT-06, #39), Transaction Script (PROJECT-07, #2), заготовка для других шаблонов (#18)
- Реестр правил, глоссарий, чек-лист разработчика и ревьюера, `.gitignore` для робота
- CONTRIBUTING, шаблоны Issue и Pull Request, проверка содержания, уровней, тегов и ссылок в CI

### Исправлено
- Пример SQL-запроса через интерполяцию строк заменен на параметризованный запрос
- Пустой `catch` в примерах работы с файлами и UI
